### B. Sub-Second Scoped Testing & Pytest Selector Passing (`cordis.mutator`)

- **Implemented Upgrade in `cordis.mutator`:** Added `shlex.split(test_rel_path)` to allow passing targeted pytest selectors (e.g. `tests/test_requests.py -k test_should_strip_auth`), reducing test cycle latency from 60s down to 0.20s (a 300x speedup).
- **Action Item for `cordis.cli`:** Add dedicated `--pytest-args` flag to `cordis probe` to pass arbitrary flags directly without overloading `test_rel_path`.

### C. Equivalent Mutant Detection & Static Reachability Filter
- **Observed Issue:** In `openai-python/_x509.py`, Cordis mutated `delay > MAX` to `>= MAX`. However, the preceding branch already handled `0 <= delay <= MAX: return delay`. Thus, the mutated branch was dead/unreachable code, resulting in an equivalent mutant that could never be killed.
- **Action Item for `cordis.mutator`:** Add a lightweight AST reachability pass before generating comparison mutations. If a boundary comparison (`>`) is strictly bounded by a previous `if` block, flag or prune the `>=` mutation to avoid reporting false surviving mutants.

### F. Overload Stub Detection & Implementation Bypass (`cordis.mutator`)
- **Observed Issue:** In typed Python libraries like `tiangolo/sqlmodel` (`Session.exec`, `Field`, `Relationship`), methods are heavily decorated with `@overload` typing signatures ahead of the actual implementation body.
- **Root Cause:** `_find_target_function_node` previously matched the first AST function node matching the target name, which was an `@overload` stub with an empty ellipsis (`...`) body, reporting 0 mutable AST nodes.
- **Implemented Upgrade in `cordis.mutator`:** Implemented `_is_overload_stub()` to identify `@overload` decorators or ellipsis-only stub bodies and automatically bypass stubs to locate the true runtime implementation body.
- **Empirical Validation:** Enabled 100% mutant discovery and kill rate across `Session.exec` in `tiangolo/sqlmodel`.
