## 1. High-Priority Engine Upgrades (Learned from Wild Invariant Hunt)

### A. Transport Stream Lifecycle & Closure Propagation (`ResponseStream.close`)
- **Observed Issue:** In client libraries with layered transport abstractions (`httpx._transports.default.ResponseStream` wrapping `httpcore`), standard integration tests verify only response payload deserialization. When the stream closure check `if hasattr(self._httpcore_stream, "close")` was inverted by Cordis Gate 2, the mutation survived upstream tests because tests never verified underlying driver resource release.
- **Action Item for `cordis.mutator`:** Add a dedicated lifecycle audit rule for stream wrapper classes. When a class conforms to `SyncByteStream` or `AsyncByteStream` and defines `.close()` / `.aclose()`, prioritize boundary checks on `hasattr` checks and ensure underlying resource cleanup is verified.

### B. Fixed Buffer Chunk Size Multi-Hop Probing (`IteratorByteStream.CHUNK_SIZE`)
- **Observed Issue:** File-like streaming implementations often define a constant buffer size (e.g. `CHUNK_SIZE = 65_536`). Upstream tests passed small strings (e.g. `b"Hello, world!"` of 13 bytes), which executed the read loop exactly once, leaving loop continuation and multi-hop chunk concatenation completely unverified against loop boundary mutations (`while not chunk:`).
- **Action Item for `cordis.ast_gate`:** Add heuristic detection for `CHUNK_SIZE` or buffer constants. When found, ensure generated test inputs or synthesis probes suggest inputs strictly greater than `2 * CHUNK_SIZE` (e.g. 150 KB) to guarantee loop re-entry verification.

### C. Security Context & Environment Trust Defaults (`trust_env=True`)
- **Observed Issue:** Flipping default security arguments (`trust_env: bool = True` -> `False` or `http1: bool = True` -> `False`) in transport constructors survived standard test suites because tests did not assert constructor default states against real environment overrides (such as `SSL_CERT_FILE`).
- **Action Item for `cordis.mutator`:** Parameter default mutations on security-critical constructors (`verify`, `trust_env`, `ssl_context`) must be flagged as high-severity invariants, triggering targeted assertion checks for environment-derived SSL contexts.
